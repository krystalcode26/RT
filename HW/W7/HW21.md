1. Encryption vs Hashing vs Encoding

These three concepts serve different purposes. 
Encryption protects sensitive data by converting it into ciphertext that can be decrypted with a key, so it's used for secure communication like HTTPS. → Credit card information

Hashing is a one-way operation that produces a fixed-length value and cannot be reversed, making it ideal for storing passwords. → Passwords

Encoding is not a security mechanism. It simply converts data into another format for transmission or storage. → Email attachments (Base64)


2. Authentication vs Authorization

Authentication answers "Who are you?", while authorization answers "What are you allowed to do?" 

Authentication verifies a user's identity using a username/password, JWT, OAuth login, or biometrics. After the user is authenticated, authorization checks their permissions or roles before allowing access to resources.

3. HTTPS, Certificates, and Key Rotation
Interview Answer

HTTPS secures communication between the client and server using TLS encryption. 
During the TLS handshake, the server presents a digital certificate issued by a trusted Certificate Authority to prove its identity, and both sides establish a shared session key for encrypted communication. 

Key rotation means replacing encryption keys or certificates regularly to reduce the impact if a key is compromised and to comply with security best practices.


Why rotate keys?

Limits damage if a key is leaked
Meets compliance requirements
Improves long-term security

4. JWT Token Structure

A JWT consists of three parts: Header.Payload.Signature
Header – specifies the token type and signing algorithm.
Payload – contains claims such as user ID, roles, and expiration time.
Signature – verifies the token hasn't been modified.

Example: xxxxx.yyyyy.zzzzz

The payload is Base64URL encoded, not encrypted, so anyone can decode it. 
Sensitive information should never be stored inside the payload.

5. OAuth 2.0 and OIDC

OAuth 2.0 is an authorization framework that allows users to grant an application limited access to their resources without sharing their password. 

OpenID Connect is built on top of OAuth 2.0 and adds authentication. 
OAuth only answers "Can this application access the resource?", while OIDC also answers "Who is the user?" by providing an ID Token that contains the user's identity information.

6. LDAP
LDAP (Lightweight Directory Access Protocol) is a protocol used to access centralized directory services containing user and organizational information. 

Companies commonly use LDAP with services like Microsoft Active Directory to manage employee accounts, authentication, and group memberships. 

Instead of maintaining users in every application, applications authenticate against the central LDAP server.

7. SQL Injection and Prepared Statements

SQL injection is a security vulnerability where an attacker injects malicious SQL commands through user input. 

Instead of concatenating strings to build SQL queries, we use prepared statements or parameterized queries, which separate SQL code from user input. This ensures user input is treated as data rather than executable SQL.
