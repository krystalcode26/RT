1. What is Angular, and why is it a "framework" rather than a library?
   
Angular is a complete platform for building web applications, maintained by Google. It's called a framework (not a library) because it provides a full, opinionated structure out of the box — routing, forms, HTTP client, dependency injection, testing tools, build tooling — and it dictates how you organize your code. A library (like a charting library) gives you tools you call when needed; a framework calls your code and controls the overall architecture ("inversion of control").

2. What is a Single Page Application (SPA), and why is Angular commonly used to build SPAs?
   
An SPA loads a single HTML page once, then dynamically updates the content in the browser via JavaScript instead of requesting new pages from the server on every navigation. Angular is well-suited for this because it includes built-in routing, component-based rendering, and state management tools that let you swap views instantly without full page reloads, giving a faster, app-like user experience.

3. Why does Angular use TypeScript by default, and what benefits does it provide?

Angular is built with and for TypeScript because it adds static typing, interfaces, and strong tooling support on top of JavaScript. In large projects, this catches errors at compile time instead of runtime, improves IDE autocomplete/navigation, makes refactoring safer, and improves overall code readability and maintainability across large teams.

4. What does "component-based architecture" mean in Angular? Give an example.

The UI is broken into small, reusable, self-contained pieces called components. Each component manages its own template (HTML), styling (CSS), and logic (TypeScript class). For example, a product-card component might contain:

product-card.component.html – the layout showing product image, name, price
product-card.component.css – its styling
product-card.component.ts – logic like @Input() product and an addToCart() method

5. What does "separation of concerns" mean?
It means dividing an application into distinct sections, each responsible for one specific job — e.g., HTML handles structure/presentation, CSS handles styling, and TypeScript handles logic and data. This keeps code organized, easier to test, easier to debug, and easier for multiple developers to work on without stepping on each other.

6. What is two-way data binding, and how does it reduce manual DOM manipulation?
Two-way data binding ([(ngModel)]) automatically keeps the component's data (model) and the UI (view) in sync — if the user types in an input field, the component's variable updates automatically, and if the variable changes in code, the UI updates automatically. This removes the need to manually write document.getElementById() or addEventListener() calls to sync data with the DOM.

7. What is Dependency Injection (DI), and why does it improve testability and loose coupling?
DI is a design pattern where a class receives the objects (dependencies) it needs from an external source rather than creating them itself. In Angular, services are "injected" into components via constructors. This improves testability because you can easily swap in mock services during unit tests, and it improves loose coupling because components don't need to know how their dependencies are constructed.

8. What is routing in Angular, and what problem does it solve?
Routing maps URL paths to specific components, letting users navigate between "pages" within an SPA without a full page reload. It solves the problem of needing multiple views/screens in an app that technically only loads one HTML page — the router swaps which component displays based on the current URL.

9. What is Node.js, and why do we need it for Angular development?
Node.js is a JavaScript runtime that lets JavaScript run outside the browser, on your machine/server. Angular development needs it because tools like the Angular CLI, npm, the dev server, and the build/compilation process all run on Node.js.

10. What is npm, and how is it similar to Maven/Gradle?
npm (Node Package Manager) is a tool for installing, managing, and sharing JavaScript packages/dependencies, and for running project scripts. It's similar to Maven or Gradle in Java because it manages a project's dependency list (package.json vs pom.xml/build.gradle), downloads them from a central repository, and defines build/run/test commands.

11. What is Angular CLI, and name at least 3 things it helps you do.
Angular CLI is a command-line tool that scaffolds and manages Angular projects. It helps you:

Generate code (ng generate component/service/module)
Build the project (ng build)
Serve it locally for development (ng serve)
Run tests (ng test)

12. What command checks your installed Node and npm versions?
node -v
npm -v

13. What does ng new do, and why run it in the correct folder?
ng new creates a brand-new Angular project with a full scaffolded folder structure, default configuration files, and initial dependencies installed. You should run it from the correct parent/workspace folder because it creates a new project directory at your current location — running it in the wrong place clutters your file system or nests projects incorrectly.

14. What is the purpose of package.json and package-lock.json? Why does package-lock.json matter in team projects?
package.json lists the project's metadata, dependencies, and available scripts. package-lock.json records the exact versions of every installed package (including nested dependencies). It matters in team projects because it guarantees that everyone on the team — and CI/CD pipelines — installs identical dependency versions, preventing "it works on my machine" bugs caused by version drift.
