1. What are the four stages of an Angular project lifecycle?
Development → Build → Testing → Deployment (create/develop the app, compile it for production, verify it works correctly, then ship it to a server).

2. What does ng serve do during development?
It compiles the Angular app and starts a local development web server (typically at http://localhost:4200), so you can view and interact with the app in a browser while developing.

3. What happens "behind the scenes" when you run ng serve?
Angular CLI uses webpack (or esbuild in newer versions) to compile TypeScript to JavaScript, bundle all files, and start an in-memory dev server. It also watches your files for changes and uses "live reload" to automatically recompile and refresh the browser whenever you save changes.

4. Why isn't the development environment designed for production usage?
The dev build is unminified, includes source maps and debugging info, isn't optimized for size or speed, and the dev server isn't hardened for security or performance at scale — it's meant for fast iteration, not for serving real users efficiently and safely.

5. What does ng build do, and why is it important that Angular doesn't "run" in production?
ng build compiles and bundles the app into static HTML/CSS/JS files optimized for production. It's important to understand that Angular itself isn't a server-side runtime in production — the output is just static files served by any regular web server (like Nginx or Apache); there's no live Angular process running on the server.

6. What optimizations happen during the build process?

Minification (removing whitespace/shortening variable names)
Tree-shaking (removing unused code)
Ahead-of-Time (AOT) compilation (templates compiled to JS before runtime)
Bundling (combining files to reduce HTTP requests)
Compression and cache-busting via hashed filenames

7. What is the dist folder, and what gets deployed from it?
dist ("distribution") is the output folder created by ng build. It contains the final compiled, optimized static files — HTML, CSS, and JavaScript bundles — which are exactly what gets uploaded/deployed to a production web server.

8. Why does Angular provide built-in testing support, and why does that matter in enterprise?
Angular ships with tools like Jasmine/Karma (unit testing) integrated by default, encouraging developers to write tests as part of normal workflow. In enterprise environments, this matters because large codebases need reliable automated testing to catch regressions, support frequent releases, and maintain code quality across large teams.

9. What is TypeScript, and what does it add on top of JavaScript?
TypeScript is a superset of JavaScript developed by Microsoft that adds static typing, interfaces, enums, generics, and advanced tooling support, then compiles down to plain JavaScript that runs in any browser.

10. Why does TypeScript help in large applications?
It catches type-related errors at compile time instead of runtime, reducing bugs that would otherwise only appear when the app is running. It also makes refactoring safer (the compiler flags broken references), improves code readability, and makes long-term maintainability easier across large teams.

11. What is npm, and how is package.json similar to pom.xml/build.gradle?
npm is the package manager for JavaScript/Node.js projects, used to install and manage dependencies and run scripts. package.json is similar to pom.xml (Maven) or build.gradle (Gradle) because it declares the project's dependencies, versions, and build/run scripts in one central configuration file.

12. What is an SPA, and how does it differ from a multi-page app?
An SPA loads one HTML page and dynamically updates content via JavaScript as the user navigates, without full page reloads. A traditional multi-page app requests a brand-new HTML page from the server for every navigation, causing a full reload each time.

13. What are the three main parts of an Angular component?

Template (HTML) – defines what's displayed in the UI
Style (CSS) – defines how it looks
Class (TypeScript) – defines the logic, data, and behavior (properties, methods, lifecycle hooks)

14. When you run ng generate component my-first-component, what files are created and what changes in app.module.ts?
It creates a folder my-first-component containing:

my-first-component.component.ts (class/logic)
my-first-component.component.html (template)
my-first-component.component.css (styles)
my-first-component.component.spec.ts (unit test file)

In app.module.ts, the CLI automatically adds an import statement for the new component and registers it in the declarations array so Angular knows about it and it can be used elsewhere in the app.
