a.	Why Spring Boot? 
Spring Boot eliminates boilerplate configuration through auto-configuration — it sets up everything based on your classpath dependencies automatically. 
It includes an embedded Tomcat server so you run your app as a plain JAR without deploying to an external server. 
The main downside is that the "magic" auto-configuration can be hard to debug, and it carries a heavier memory footprint than lightweight alternatives.

b.	How to Start a Spring Boot Project from Scratch 
Go to start.spring.io, select your dependencies (Web, JPA, etc.), and download the generated project. Add a main class annotated with @SpringBootApplication and call SpringApplication.run() — that's all you need to boot up. 
Run it with mvn spring-boot:run or java -jar app.jar.

c.	@Controller vs @RestController 
@Controller is used for server-side UI — it returns a view name (like a Thymeleaf template) resolved by a view resolver. 
@RestController is @Controller + @ResponseBody, meaning every method automatically serializes the return value to JSON instead of resolving a view. 
Use @Controller for web pages, @RestController for REST APIs.

d.	@PathVariable vs @RequestParam 
@PathVariable extracts a value embedded in the URL path — e.g. GET /users/42 where 42 is the variable. 
@RequestParam extracts a value from the query string — e.g. GET /users?name=Alice. Use @PathVariable to identify a specific resource, and @RequestParam for optional filters or pagination.

e. @RequestBody vs @ResponseBody 
@RequestBody deserializes the incoming JSON request body into a Java object — used on method parameters. @ResponseBody serializes the outgoing Java object into a JSON response — used on method return values. 
With @RestController, @ResponseBody is applied automatically so you don't need to declare it explicitly.

f. Mapping Annotations 
@RequestMapping is the base annotation that maps HTTP requests to methods, supporting all HTTP methods with a method attribute. 

The shorthand annotations — @GetMapping, @PostMapping, @PutMapping, @DeleteMapping — are just specialized versions of @RequestMapping for each HTTP verb. Typically you put @RequestMapping("/api/users") on the class as a base path, then use the specific annotations on each method.

g. What is Spring Actuator? 
Spring Actuator exposes production-ready endpoints to monitor and manage your running application out of the box. 
Key endpoints include /actuator/health for app status, /actuator/metrics for memory and CPU stats, and /actuator/beans for all registered Spring beans. You enable it by adding spring-boot-starter-actuator and configuring which endpoints to expose in application.properties.

h. How to Achieve Async in Spring Boot 
Add @EnableAsync to your main class, then annotate any method with @Async to run it in a background thread pool instead of the calling thread. The method should return CompletableFuture<T> so the caller can handle the result asynchronously. You can configure the thread pool size by defining a custom ThreadPoolTaskExecutor bean.

i. How Spring Handles Exceptions 
Spring handles exceptions globally using @RestControllerAdvice — a class that intercepts exceptions thrown from any controller. 
Inside it, @ExceptionHandler(SomeException.class) methods catch specific exception types and return the appropriate HTTP status and response body. This keeps try/catch blocks out of your controllers and centralizes all error handling in one place.

j. How Spring Validates Data 
Add spring-boot-starter-validation, then annotate your model fields with constraints like @NotNull, @Email, or @Size. Trigger validation by adding @Valid to the @RequestBody parameter in your controller method. 
If validation fails, Spring throws MethodArgumentNotValidException, which you can catch in @RestControllerAdvice to return a clean error response.

k. How Spring Does Logging 
Spring Boot uses SLF4J + Logback by default — just inject a Logger with LoggerFactory.getLogger() and call log.info(), log.debug(), log.error(). You control log levels per package in application.properties with logging.level.com.app=DEBUG and write to a file with logging.file.name=app.log. No extra dependencies needed — it works out of the box.

l. Cache Hit vs Cache Miss 
A cache hit means the requested data was found in the cache — returned immediately with no database call, giving fast response times. 
A cache miss means the data wasn't in the cache — Spring fetches it from the database, stores it in the cache, then returns it. 
Over time, more hits and fewer misses means less DB load and better performance.

m. Redis Basics 
Redis is an in-memory key-value store used for caching, session storage, and pub/sub messaging — with microsecond latency because everything lives in RAM. 
In Spring Boot, you add spring-boot-starter-data-redis and use @Cacheable, @CacheEvict, and @CachePut to manage cached data automatically. 
Redis also supports TTL (Time To Live) so cached keys expire automatically, and it can persist data to disk via RDB snapshots or AOF logging.

n. @RestControllerAdvice vs @ControllerAdvice 
@ControllerAdvice handles exceptions globally across all controllers but requires @ResponseBody on each handler method to return JSON. 
@RestControllerAdvice is simply @ControllerAdvice + @ResponseBody built in — every handler method automatically returns JSON without extra annotations. 
For REST APIs always use @RestControllerAdvice — it's cleaner and removes boilerplate.
