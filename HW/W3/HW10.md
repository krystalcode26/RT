1. What is AOP? 
Aspect-Oriented Programming lets you separate repetitive cross-cutting concerns from business logic; it defines When and Where to execute the @Pointcut.
It includes two types of AOP @RestControllerAdvice and @Aspect

@RestControllerAdvice is a Spring bean that intercepts exceptions thrown from any @RestController. You declare which exception type to catch as the method parameter @ExceptionHandler, and return the appropriate HTTP response @ResponseStatus.
@Aspect - Instead of copy-pasting the same logging code into every method, you define it once in an Aspect and Spring applies it automatically wherever you specify. This keeps your business code clean and focused on what it does.
 
3. JoinPoint and Aspect in AOP 
Aspect is the class that contains your cross-cutting logic 
Ex: a LoggingAspect that logs every method call. 
JoinPoint is a specific moment during program execution.
Ex: a method being called — where that logic can be applied. 
Together, you define an Aspect that intercepts Join Points matching your Pointcut expression, letting you run extra logic before, after, or around the target method.

4. What are Aspect, JoinPoint, Pointcut, Advice, and Target?
An Aspect is a class that contains a cross-cutting logic. It contains the what (advice) and the where (pointcut) together.
A JoinPoint is a specific point during method execution. It carries runtime info about that moment.
A Pointcut (The "Where" Selector) is an expression that selects which JoinPoints the advice should apply to. Think of it as a filter or query over your methods.
Advice (“The "What" Logic”) is the actual code that runs at a JoinPoint. There are 5 types:@Before Before method executes, @AfterReturning	After successful return, @AfterThrowing	After exception is thrown, @After	Always after (like finally), @Around	Wraps entire execution.
Target is the original bean whose method is being intercepted. Spring wraps it in a proxy — the target itself has no knowledge of the aspect.
 
5. ApplicationContext vs BeanFactory
Both are Spring IoC containers used to manage beans. With BeanFactory, you must register post-processors manually
ApplicationContext extends BeanFactory, provides additional features such as AOP support, event handling, and internationalization, making it the preferred choice in Spring Boot applications.
BeanFactory is the Basic Container which is the root interface for Spring's IoC container. Uses lazy initialization, beans are created only when getBean() is called
 
6. How Does Spring MVC Work?
Spring MVC follows the Front Controller pattern, where the DispatcherServlet receives all incoming requests and routes them to the appropriate controller. The controller calls the service and repository layers, then returns a response, usually in JSON format for REST APIs.
 
7. How Does @Autowired Work?
@Autowired enables Spring to automatically inject a dependency from the IoC container into a class. Spring searches for a matching bean by type and injects it at runtime, reducing the need for manual object creation.
 
8. @Autowired and @Qualifier
@Autowired injects a bean by type, but if multiple beans of the same type exist, Spring cannot determine which one to use. @Qualifier is used with @Autowired to specify the exact bean that should be injected.
 
9. Two Use Cases for @PostConstruct and @PreDestroy
@PostConstruct runs after a bean is created and is commonly used to initialize resources, load cache data, or validate configuration. 
@PreDestroy runs before a bean is destroyed and is often used to close database connections, release resources, or save in-memory data before shutdown.

Use Case: Initializing a cache or resource after dependency injection
@Component
public class ProductCacheService {

    @Autowired
    private ProductRepository productRepository;

    private Map<Long, Product> cache;

    @PostConstruct
    public void initCache() {
        // Runs after productRepository is injected — safe to use it here
        cache = productRepository.findAll()
                    .stream()
                    .collect(Collectors.toMap(Product::getId, p -> p));
        System.out.println("Cache initialized with " + cache.size() + " products.");
    }
}

@PreDestroy — Run cleanup logic before the bean is destroyed
Use Case: Closing a database connection or releasing external resources
Without @PreDestroy, the connection might remain open when the Spring context shuts down, leading to resource leaks or locked database handles.
@Component
public class DatabaseConnectionManager {

    private Connection connection;

    @PostConstruct
    public void openConnection() {
        connection = DriverManager.getConnection("jdbc:mysql://localhost/mydb");
        System.out.println("DB connection opened.");
    }

    @PreDestroy
    public void closeConnection() {
        if (connection != null && !connection.isClosed()) {
            connection.close();
            System.out.println("DB connection closed gracefully.");
        }
    }
}
