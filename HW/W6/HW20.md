1. Unit test and integration test
   
A unit test checks one small piece of code, such as a method or class, by itself.
An integration test checks whether multiple parts of the application work together correctly.

Example for a rewarding project:
Unit test: test calculateRewardPoints(user) to verify the points are computed correctly for different purchase amounts.
Integration test: test the reward service + database + API together to verify that when a user makes a purchase, points are saved and returned correctly.

2. TDD vs BDD vs DDD
TDD	- Test-Driven Development:	Write a failing test first, then code to pass it.
BDD	- Behavior-Driven Development:	Describe system behavior in business-friendly language.
DDD	- Domain-Driven Design: Design software around the business domain and its rules.

TDD is about writing tests before code, BDD is about writing tests around behavior, and DDD is about structuring software around the business domain.

4. What is JUnit
JUnit is a Java testing framework used to write and run repeatable unit tests.
It provides annotations and assertions that make testing easier and automated.

6. What is Mockito
Mockito is a Java mocking framework used in unit tests to create fake objects and isolate the class being tested.
It is useful when your code depends on databases, APIs, or other services you do not want to call in a unit test.

8. How do you test your application
   
A common approach is:
Unit tests for individual methods and classes.
Integration tests for APIs, database, and service interactions.
End-to-end tests for complete user flows.
Run tests automatically in CI/CD after each change.
This matches the usual testing pyramid approach where unit tests are the majority and integration/end-to-end tests cover bigger flows.

6. Tools for code quality analysis
   
Common tools include SonarQube and SAST tools. 
They analyze code for bugs, vulnerabilities, duplicated code, maintainability issues, and code smells without running the program.

8. Authentication vs Authorization

Authentication answers: “Who are you?”
Authorization answers: “What are you allowed to do?”

Authentication verifies identity, while authorization checks permissions after identity is confirmed.

9. Encryption vs Hashing vs Encoding
   
Term	           Purpose	                              Reversible?

Encoding	  Change format for interoperability	          Yes

Encryption	Protect confidentiality	                      Yes, with a key

Hashing	    Check integrity / store secrets safely	      No

Encoding is for data representation, encryption is for confidentiality, and hashing is for integrity.

10. How do you secure your application

Use HTTPS.
Validate all input.
Use strong authentication and authorization.
Store passwords with hashing, not encryption.
Keep secrets safe.
Use short-lived tokens.
Apply logging, monitoring, and rate limiting.
Keep dependencies updated and scan for vulnerabilities.

For APIs, security guidance also recommends validating OAuth redirect URIs, using the state parameter, and verifying JWT signatures and expiration.

10. What is JWT
    
JWT stands for JSON Web Token. It is a compact token format used to transmit claims between parties, often for authentication and authorization in web applications and APIs.
A JWT usually has three parts: header, payload, and signature.

12. What is OAuth2
OAuth 2.0 is an authorization framework that lets a third-party application access a user’s resources without sharing the user’s password.
It is commonly used for delegated access and often works with tokens
